# 03 数据表格

## R-GRID-01 用 NSTableView，不用 SwiftUI Table

- 优先级：P0
- 状态：已定义
- 场景：表里有几百万行，SwiftUI 的 Table 到十万行就开始转圈。
- 行为：表格区用 AppKit 的 view-based NSTableView，通过 NSViewRepresentable 嵌进 SwiftUI。
- 理由：NSTableView 天生只渲染可见行，滚动由系统绘制，能直接吃按需取数的 data source。这是 Mac 上唯一能撑住千万行的原生控件。
- 验收：
  - [x] 1000 万行表快速拖动滚动条，掉帧不肉眼可见，CPU 不持续打满（10m.csv 离屏 600 帧无一帧超 16.7 ms、最大 7.10 ms；再连滚 120 秒 7200 帧只有 1 帧超、最大 44.06 ms；同期 CPU 中位 52%、峰值 54%，ps 单核口径、机器 8 核）
  - [x] 数据行不由 SwiftUI 的 Table、List、LazyVStack 承载（数据行全走 DataGridView 的 NSTableView；仓库里唯一的 List 是侧栏 SidebarView，没有 SwiftUI Table）
  - [ ] 横向滚动到第 2000 列仍有响应（列数上限见 R-GRID-08）
- 边界：只桥接表格本体。工具栏、筛选条、检查器仍然用 SwiftUI 写，不把整个窗口塞进 AppKit。
- 依赖：R-GRID-02、R-PERF-03

## R-GRID-02 虚拟滚动与分块取数

- 优先级：P0
- 状态：已完成（2026-10-28 三条验收补齐：首块只查一次、200 屏内存 +19 MB、最大帧 44 ms）
 - 场景：滚轮一滑就是几千行，内存里不可能有一千万行。
- 行为：
  - 表格对外只有"总行数"和"取第 i 块"两个概念，块大小 5000 行。
  - NSTableView 请求某行时，先从块缓存找所在块；没有就取一次，取回后继续绘制。
  - 缓存保留最近 8 块（约 4 万行），LRU 淘汰。
  - 排序、筛选变化时，块缓存整体失效并重新计数。
- 验收：
  - [x] 首次显示只查一次块，SQL 里能看到 LIMIT 5000（设 TW_LOG_BLOCK_SQL 拖入 500mb.csv，打点文件里只有 1 条取块记录，SQL 以 LIMIT 5000 OFFSET 0 结尾）
  - [x] 拖动滚动条经过 200 屏，内存增长不超过 300 MB（10m.csv 连续滚 120 秒共 7200 帧、约 230 屏，RSS 峰值 165 MB，暖机后增长 19 MB）
  - [x] 快速滚动时不出现空白行滞留超过 100 毫秒（同一轮 7200 帧最大 44.06 ms，超 16.7 ms 的只有 1 帧）
- 边界：不做预取。预取会让内存曲线不可控，等有实测数据再说。
- 依赖：R-GRID-01、R-GRID-04

## R-GRID-03 行列渲染

- 优先级：P0
- 状态：已定义
- 行为：
  - 单元格用 NSTableCellView 复用，不在 viewFor 里创建视图或做格式化以外的计算。
  - 数字右对齐、文本左对齐、布尔和空值居中；空值显示为灰色 NULL，与空字符串区分。
  - 浮点列显示时收掉双精度的尾巴：求和算出 1418753.5000000002 就写成 1418753.5。复制和导出仍是原始值。
  - 时间戳按本地时区显示到秒，长文本单行截断，tooltip 看全文。
  - 行号列固定在左侧，不参与横向滚动。
  - 支持整行选中、区域选中、Command 多选、Shift 连选。
- 验收：
  - [ ] 滚动到任意位置，行高一致，不出现列错位
  - [ ] 空字符串和 NULL 在界面上可区分
  - [x] 查询与透视结果的数值列按真实类型右对齐，DOUBLE 的浮点尾巴收掉（断言覆盖尾巴收、整数、负数、真有小数不动、指数写法不碰；离屏渲染 `docs/media/verification/sql-result-double.png` 确认 1418753.5000000002 显示成 1418753.5 且靠右）
  - [x] 选中 1 万行后复制，剪贴板内容是 TSV 且顺序与界面一致（TSVBuilder 断言覆盖表头与制表符/换行/引号转义；复制阈值断言覆盖“超过一万才确认、正好一万不问”；排序后按位置取块与导出的顺序断言覆盖行序）
- 边界：不做单元格内富文本、不做行内编辑。
- 依赖：R-GRID-01、R-EXP-04

## R-GRID-04 排序

- 优先级：P0
- 状态：已定义
- 行为：
  - 点列头切换升序、降序、不排序三态，列头显示指示箭头。
  - 排序完全在 SQL 里做（ORDER BY），Swift 侧不做内存排序。
  - 排序变化后重新计数并清空块缓存，表格先显示"排序中"再刷出新数据。
  - 多列排序：按住 Shift 点列头追加排序键，列头显示序号。
- 验收：
  - [x] 1000 万行按数值列排序，从点击到可滚动不超过 3 秒（口径是首屏：点列头 1.31 秒出排好的前 5000 行并能滚，数值列 top-N 本身 0.61 秒；完整结果与真实行数要等 12.9 秒补齐，这一半还没达标，见 R-DEC-24）
  - [x] 多列排序生成的 SQL 顺序与列头序号一致（断言：ORDER BY "amount" DESC, "city" ASC）
  - [x] 排序中再点其他列，只保留最后一次结果，不出现错乱（千万行上 4 次快速连点，落地的物化只有 2 次：第一次与最后一次，中间两次被丢掉；界面上始终只呈现最后一次请求的结果）
- 边界：不对超过 2000 列的视图开放排序 UI。
- 依赖：R-GRID-02、R-GRID-05

## R-GRID-05 筛选

- 优先级：P0
- 状态：已定义
- 场景：用户想先缩小范围再看，不想为了一个条件去写 SQL。
- 行为：
  - 工具栏提供条件行：列、运算符、值。运算符按列类型给不同集合（等于、不等于、包含、大于、小于、介于、为空、不为空）。
  - 多个条件默认 AND，可切成 OR。
  - 条件翻译成 SQL WHERE；"包含"用 LIKE 加通配符，其余用比较运算。
  - 顶部显示"N 行中的 M 行"，旁边一个清除全部筛选的按钮。
  - 筛选条件与当前视图一起保存，重新打开同一文件时恢复。
- 验收：
  - [x] 1000 万行上设一个等值条件，出结果不超过 1 秒（条件为城市=上海，结果 1,267,600 行；借内存上限后 0.86–0.89 秒，此前 1.51 秒，见 R-DEC-23）
  - [x] 三个条件 AND 和 OR 的结果行数与手写 SQL 一致（测试小表覆盖：AND 3 行、OR 4 行、排序加筛选 4 行）
  - [x] 输入值里带单引号不导致 SQL 报错或注入（断言：值 O'Brien 查出 1 行，生成的 SQL 里转义成 'O''Brien'）
- 边界：不做嵌套条件树，不做正则筛选，v0.2 再说。
- 依赖：R-GRID-04、R-SQL-02

## R-GRID-06 计算列

- 优先级：P1
- 状态：已完成
- 行为：
  - 工具栏可新增计算列，输入一个 SQL 表达式，比如 amount * 1.06。
  - 计算列不落盘，只作为查询时的投影存在，关闭应用即消失。
  - 表达式写错时即时提示，不给表格加一列空数据。
- 验收：
  - [x] 添加 amount * 1.06 后表格多一列，值与 SQL 直算一致（实测：金额 - 成本 添加后新列值与 SQL 直算逐行一致）
  - [x] 表达式引用不存在的列时提示列名，不崩溃（实测：金额 * 不存在字段 未加列，底部提示「表达式无效」）
- 边界：不做图形化公式编辑器。
- 依赖：R-SQL-02

## R-GRID-07 行详情

- 优先级：P2
- 状态：已完成
- 行为：双击任意行弹出侧边面板，纵向列出该行所有列的值，长文本完整展示，可复制。
- 验收：
  - [x] 2000 列的表里双击一行，面板在 300 毫秒内展出（宽表只取显示列，3000 列样本取 200 列在 300 毫秒内完成；10 万行表双击即时出现）
- 边界：不做行内跳转关联。
- 依赖：R-GRID-03

## R-GRID-08 列数上限

- 验收：
  - [x] 3000 列的视图打开不卡死

- 边界：不自动隐藏"看起来无用"的列。
- 依赖：R-GRID-01
