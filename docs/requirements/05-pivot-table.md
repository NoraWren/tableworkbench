# 05 透视表

## R-PVT-01 拖拽透视

- 优先级：P1
- 状态：已定义
- 场景：想看"每个客户每个月的金额合计"，写 SQL 又要回忆 GROUP BY。
- 行为：
  - 透视面板有四个区域：行、列、值、筛选。
  - 从左侧字段列表拖字段到区域，拖错了可以再拖出来。
  - 值区域支持聚合：求和、计数、去重计数、平均、最大、最小。
  - 结果实时刷新，改动后 500 毫秒内出结果。
  - 透视结果可另存为视图，也能直接导出。
- 验收：
  - [ ] 把客户拖到行、月份拖到列、金额拖到值，结果与手写 GROUP BY 一致
  - [ ] 四个区域都为空时提示"至少放一个字段到行或值"，不报错
  - [ ] 拖拽过程中不出现界面卡顿
- 边界：不做计算字段、不做百分比布局、不做下钻到明细，v0.2 再说。
- 依赖：R-PVT-02、R-PVT-03、R-SQL-01

## R-PVT-02 聚合下推

- 优先级：P0
- 状态：已定义
- 行为：透视在 DuckDB 里用一条 GROUP BY 语句算完，Swift 侧只做行列转置和表头排列，不做逐行累加。
- 验收：
  - [ ] 1000 万行上做两级分组求和，耗时不超过 2 秒
  - [ ] 生成 SQL 能在 SQL 抽屉里复现同样结果
- 边界：不做中间结果的本地缓存到磁盘。
- 依赖：R-SQL-02

## R-PVT-03 基数保护

- 优先级：P1
- 状态：已定义
- 场景：把订单号拖到行，一拖就是一百万行，界面直接卡死。
- 行为：
  - 拖入字段时先查该列的去重计数（同一会话内缓存）。
  - 行维度去重值超过 5000、列维度超过 200 时，弹提示说明会生成多大结果，让用户确认或改用筛选。
  - 用户确认后仍可继续，不硬性阻止。
- 验收：
  - [ ] 把高基数字段拖到行时在 300 毫秒内给出提示
  - [ ] 已确认过的同一字段不重复提示
- 边界：不做自动降采样。
- 依赖：R-INSP-02

## R-PVT-04 结果表头与空值

- 优先级：P1
- 状态：已定义
- 行为：
  - 行维度多级时表头逐级合并显示，列维度横向展开，左上角留空。
  - 空值分组显示为 (空)，与空字符串 (空白) 区分。
  - 冻结首列和表头，滚动时保持可见。
- 验收：
  - [ ] 两级行维度、两级列维度的表头层级正确
  - [ ] 含 NULL 的分组单独成一列，不被丢掉
- 边界：不做斜线表头和复杂样式。
- 依赖：R-PVT-01
