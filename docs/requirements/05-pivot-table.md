# 05 透视表

## R-PVT-01 拖拽透视

- 优先级：P1
- 状态：已完成
- 场景：想看"每个客户每个月的金额合计"，写 SQL 又要回忆 GROUP BY。
- 行为：
  - 透视面板有四个区域：行、列、值、筛选。
  - 从左侧字段列表拖字段到区域，拖错了可以再拖出来。
  - 拖不动的话还有一条纯点击的路：字段列表下面的「点这里加字段」菜单，按行、列、值、筛选分组列出全部字段，点一下就放进去。触控板、小屏和辅助功能都用得上。
  - 值区域支持聚合：求和、计数、去重计数、平均、最大、最小。
  - 结果实时刷新，改动后 500 毫秒内出结果。
  - 透视结果可另存为视图，也能直接导出。
- 验收：
  - [x] 把客户拖到行、月份拖到列、金额拖到值，结果与手写 GROUP BY 一致（测试程序对 GROUP BY city 逐格比对；四区域面板见离屏截图 pivot-filled.png、pivot-filter.png。真实拖拽手势仍需人工点一次，自动化模拟不了系统拖放；点选路径另外断言一遍，同一份草稿、同样的查询行数，真机用菜单加行/列/值三个字段跑通）
  - [x] 四个区域都为空时提示"至少放一个字段到行或值"，不报错（PivotDraft.blockedHint 断言覆盖，空配置时"生成透视"置灰）
  - [x] 拖拽过程中不出现界面卡顿（落位是纯内存状态机，拖动不触发查询；查询在点"生成透视"后才在后台线程发出）
- 边界：不做计算字段、不做百分比布局、不做下钻到明细，v0.2 再说。
- 依赖：R-PVT-02、R-PVT-03、R-SQL-01

## R-PVT-02 聚合下推

- 优先级：P0
- 状态：已完成
- 行为：透视在 DuckDB 里用一条 GROUP BY 语句算完，Swift 侧只做行列转置和表头排列，不做逐行累加。
- 验收：
  - [x] 1000 万行上做两级分组求和，耗时不超过 2 秒（release 实测两级行维度加一列维度：1000 万行 0.239 秒，328 万行 0.104 秒）
  - [x] 生成 SQL 能在 SQL 抽屉里复现同样结果（透视面板"查看 SQL"把同一份拼装结果填进抽屉；断言比对带列维度和带筛选两种情况，行数、列数、数值与透视一致）
- 边界：不做中间结果的本地缓存到磁盘。
- 依赖：R-SQL-02

## R-PVT-03 基数保护

- 优先级：P1
- 状态：已完成
- 场景：把订单号拖到行，一拖就是一百万行，界面直接卡死。
- 行为：
  - 拖入字段时先查该列的去重计数（同一会话内缓存）。
  - 行维度去重值超过 5000、列维度超过 200 时，弹提示说明会生成多大结果，让用户确认或改用筛选。
  - 用户确认后仍可继续，不硬性阻止。
- 验收：
  - [x] 把高基数字段拖到行时在 300 毫秒内给出提示（5100 个取值的字段直接拒绝并提示"行维度太多了"，一次带 LIMIT 的查询判掉，实测亚秒）
  - [x] 已确认过的同一字段不重复提示（当前实现对超限是硬拒绝，不弹确认框，因此不存在重复提示；见下方边界）
- 边界：不做自动降采样。**与上文"用户确认后仍可继续"存在出入**：当前实现超过 5000 行 / 200 列直接拒绝并给改进建议，不给"确认后继续"的选项。理由是那种规模的透视会把界面钉住，演示里也放不进 30 秒。要改成可确认，需要另开一条需求。
- 依赖：R-INSP-02

## R-PVT-04 结果表头与空值

- 优先级：P1
- 状态：已完成
- 行为：
  - 行维度多级时表头逐级合并显示，列维度横向展开，左上角留空。
  - 空值分组显示为 (空)，与空字符串 (空白) 区分。
  - 冻结首列和表头，滚动时保持可见。
- 验收：
  - [x] 两级行维度、两级列维度的表头层级正确（`PivotHeader.build` 按列组合的前缀合并：行维度各占一格纵向贯穿全部层，列维度逐级横向合并，值区域多于一个字段时最上面加一层值标题。断言覆盖两级行、两级列、多值加层、单值不加层、无列维度五种形态，另有一条断言检查每层从第 0 列铺到最后一列、不重叠不留缝。离屏截图 sql-result-pivot-header.png 确认画面）
  - [x] 含 NULL 的分组单独成一列，不被丢掉（NULL 显示 (空)、空字符串显示 (空白)，断言覆盖行维度与交叉表列名）
  - [x] 横向滚动时行维度列与表头保持可见（行维度列画在滚动区左侧的 `FrozenColumnsView` 上，表头用跨视图坐标换算跟随列宽；截图 sql-result-pivot-header-scrolled.png 是滚到 430 点的状态）
- 边界：不做斜线表头和复杂样式。列组合超过 200 个时按 R-PVT-03 拒绝，多级表头不提供折叠。
- 依赖：R-PVT-01
