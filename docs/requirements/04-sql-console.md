# 04 SQL 抽屉

## R-SQL-01 编辑器与执行

- 优先级：P1
- 状态：已定义
- 场景：想算一个数，但不想为此去开终端。
- 行为：
  - 窗口底部一个可收起的 SQL 抽屉，拖上边缘可调高度，快捷键 Command+R 运行，Command+J 收起展开。
  - 编辑器用 NSTextView 包一层，等宽字体，光标行高亮，不追求完整语法分析。
  - 快捷键运行：有选区只运行选区，没有选区运行全文。
  - 结果落到表格区，与打开文件的表格共用同一个数据网格组件。
  - 执行中显示耗时和已用时间，可随时取消。
- 验收：
  - [ ] Command+R 在有选区时只执行选中的语句
  - [ ] 执行 1000 万行的 GROUP BY，结果在 2 秒内出现，期间界面不冻结
  - [ ] 点取消后 200 毫秒内回到可编辑状态，不留后台线程
- 边界：不做多语句事务、不做 DDL 持久化，见 R-SQL-02。
- 依赖：R-GRID-01、R-SQL-03

## R-SQL-02 只读边界

- 优先级：P0
- 状态：已完成
- 场景：用户把 Cmd+V 粘进来一段别人给的 SQL，里面可能带 DROP 或者 DELETE。
- 行为：
  - 连接以只读方式打开，DuckDB 层面拒绝写操作，不只靠界面拦。
  - 界面层再拦一次：以 CREATE、DROP、INSERT、UPDATE、DELETE、ALTER、COPY 开头的语句直接提示"分析模式只读"。
  - 允许 CREATE 临时表吗：v0.1 允许 CREATE TEMP TABLE 和 CREATE TEMP VIEW，因为它们不落盘，能支撑"先算一步再接着算"。
  - 用到的表统一以视图形式挂在内存连接上，文件本身永远只读。
- 验收：
  - [x] 执行 DROP TABLE 时被拒，原始文件没有被修改（用文件哈希对比验证）
  - [x] 执行 CREATE TEMP TABLE 成功，关闭会话后临时表消失
  - [x] 只读限制写在 DuckDBKit 里，绕过界面直接调用也拦得住
- 边界：不做权限分级和用户角色。
- 依赖：R-SQL-01、R-DEC-02

## R-SQL-03 结果与错误

- 优先级：P1
- 状态：进行中
- 行为：
  - 成功：显示行数、耗时、结果表格。结果最多 100000 行，超出时明确提示「只显示前 100000 行」。上限从 100 万降到 10 万是因为结果全部读进内存，100 万行会卡住界面。
  - 失败：错误卡片显示一句人话解释，并可在「查看技术细节」里展开 DuckDB 原文。语法高亮的定位还没做。
  - 空结果：显示"0 行"，不显示空白表格。
  - 结果表另存为视图：v0.1 不做。
- 验收：
  - [x] 语法错误时弹出错误卡片，原文可在技术细节里查看（暂不高亮位置）
  - [ ] 结果另存为视图后能在下一条 SQL 里按名字查询（v0.1 不做，验收项保留）
- 边界：不做执行计划可视化。
- 依赖：R-SQL-01

## R-SQL-04 历史与片段

- 优先级：P2
- 状态：已完成
- 行为：
  - 每次执行的语句进本地历史，按时间倒序，最多 200 条，可搜索、可一键填回编辑器。
  - 用户可把常用语句存成片段，起个名字，出现在侧栏。
  - 历史只存在本机，不上传。
- 验收：
  - [x] 重启应用后历史还在
  - [x] 搜索历史关键词能命中语句中间的词
  - [x] 当前语句能存成命名片段，同名覆盖不重复
  - [x] 点侧栏片段把语句填回编辑器，不自动执行
  - [x] 片段能删除，侧栏与本地存储同步更新
- 边界：不做团队共享、不做云端同步。
- 依赖：R-SQL-01

## R-SQL-05 表名与列名自动补全

- 优先级：P2
- 状态：已完成
- 行为：输入表名或列名前缀时弹出候选，用 Tab 或回车接受；候选来自当前连接里的表和视图。
- 验收：
  - [x] 输入 sel 补成 SELECT 不打扰正常输入
  - [x] 候选列表里能看到当前打开文件的表名
  - [x] 字符串与注释里不弹候选，已完整敲出的词不重复给出
- 边界：不做跨库、跨会话的语义补全。
- 依赖：R-SQL-01
