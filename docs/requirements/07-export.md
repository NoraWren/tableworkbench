# 07 导出

## R-EXP-01 导出表格

- 优先级：P1
- 状态：进行中
- 场景：算完了要交给别人，或者接着用。
- 行为：
  - 菜单 File → Export，或结果区右键导出。
  - 格式三种：CSV（UTF-8 带 BOM）、Parquet、剪贴板 TSV。
  - 默认导出当前视图：包括筛选和排序结果，不含隐藏列。
  - 导出前让用户选范围：全部行、当前筛选结果、选中行。
- 验收：
  - [x] 导出 100 万行 CSV，文件能被 Excel 打开且中文不乱码（用 500mb.csv 的 3,266,000 行整表导出：494 MB、2.815 秒，文件头是 EF BB BF，中文列名与「华南」「客户001」原样；再用应用自己的导入器读回 3,266,000 行 × 20 列、编码识别为 UTF-8 (BOM)。Excel 本体没装，没在 Excel 里真正打开过）
  - [x] 导出 Parquet 后用 DuckDB 命令行读回，行数和列类型一致（同一份数据导出 130 MB、1.205 秒，用 DuckDB 读回 3,266,000 行 × 20 列，类型与源表一致：订单号等文本列 VARCHAR、数量 BIGINT、单价/金额/成本/毛利 DOUBLE）
  - [ ] 撤销导出不删除已写出的文件，但界面提示文件位置
  - [x] 导出前能选“全部行 / 当前筛选结果 / 选中行”，导出行数与选择一致（选中 4 行导出 4 条记录，顺序与表格相同）
- 边界：不做导出 Excel，见 R-EXP-03。
- 依赖：R-EXP-02

## R-EXP-02 导出进度与取消

- 优先级：P1
- 状态：已定义
- 行为：
  - 超过 10 万行的导出显示进度条，可取消。
  - 导出在后台线程，界面不冻结。
  - 取消后删除不完整文件，不留半截 CSV 让人误用。
- 验收：
  - [ ] 导出 500 万行期间界面能滚动（导出本来就在 Task.detached 里跑，状态栏同时显示转圈与「停止」；但没有在 500 万行的导出窗口里真滚一次，未验）
  - [x] 取消后目标目录里没有残留文件（导出一律先写带随机后缀的 .tmp- 临时文件，成功才改名到目标；失败或取消时临时文件被删掉。断言：写到不存在的目录会报错，且工作目录里没有任何 tmp- 残留）
- 边界：不做断点续传。
- 依赖：R-EXP-01

## R-EXP-03 不导出 Excel

- 优先级：P1
- 状态：已完成
- 行为：v0.1 不提供 xlsx 导出。用户选 CSV 时，若提示需要 Excel 可读，说明用 CSV 加 UTF-8 BOM 已能在 Excel 正常打开。
- 原因：写 xlsx 要额外依赖和一堆格式兼容测试，对"挣名声"没有帮助。
- 验收：
  - [x] 导出面板里没有 xlsx 选项，也不给灰色不可点的假入口
- 边界：v0.2 视需求再加。
- 依赖：R-EXP-01

## R-EXP-04 复制

- 优先级：P1
- 状态：已完成
- 行为：
  - Command+C 复制选中区域，格式为 TSV，带表头（可在设置关掉）。
  - 复制时保留原始值精度，不按界面显示的四舍五入值复制。
  - 复制 1 万行以内直接写入剪贴板；超过时提示行数并让用户确认。
- 验收：
  - [x] 复制的小数在粘贴到文本编辑器后与源数据一致
  - [x] 复制包含换行符的单元格时，粘贴结果不串行（用引号包裹）
  - [x] 选中超过 1 万行时先确认，取消则剪贴板不动（断言真跑 GridTableView.copy：10001 行触发确认、返回取消时剪贴板保持原内容、返回确认时写入含表头的 TSV）
- 边界：不做图片复制、不做带格式复制。
- 依赖：R-GRID-03
