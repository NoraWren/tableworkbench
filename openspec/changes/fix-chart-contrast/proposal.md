# Proposal

## 对应需求

- R-VIZ-04：深色模式与可读性，柱、线、饼与文字对比度不低于 4.5:1。
- R-INSP-03：分布图的柱子和文字在深色模式下达到 WCAG AA。

## Why

离屏渲染把图抓成位图逐个量过之后，发现三处不达标。截图是 Display P3，先经 ImageCms 转 sRGB 再算 WCAG 对比度。

| 项 | 改前浅色 | 改前深色 |
|---|---|---|
| 柱子（accent@0.85） | 2.95:1 | 2.78:1 |
| 坐标文字（系统次要色） | 3.84:1 | 5.08:1 |
| 网格线 | 1.24:1 | 1.36:1 |
| 检查器直方图柱 | 3.97:1 | 3.67:1 |
| 检查器分组标题「统计」 | 1.90:1 | 2.69:1 |

根因有两层。系统强调色是按浅色底挑的，压到深色底上本来就不够；再叠一层 0.85 或 0.6 的透明度跟底混，掉得更狠。文字用的系统次要色是 50% 左右的半透明色，压在浅色底上只有 3.84:1。

还有一个量不出结论的问题：离屏渲染的底色由宿主补，跟 `drawingBackground()` 返回的值不是同一个（一个是 236/50，一个是 255/30），对比度算得再准也是空算。

## What Changes

- 新增 `ChartPalette`：按当前画布色保留色相、沿明度轴把颜色推到目标对比度，输出动态色，切换深浅色时重新解析。
- 图表画布色由 `ChartView` 自己铺（`ChartPalette.canvas`），取色与渲染用同一个值。
- 主色目标 6.6:1、次级色 4.6:1、文字 4.6:1、网格线 1.35:1。目标值带余量，因为 P3 转 sRGB 有零点几的取整误差。
- 主色与次级色留出明度差，饼图相邻扇区、色弱与黑白打印都分得开；饼图扇区再描一道 1 像素画布色。
- 去掉柱、线、饼上的半透明叠色，改铺实色。
- 检查器直方图柱改用同一套配色；分组标题「统计」改为显式次要色。
- 检查器统计块抽成 `ColumnStatsRows`，离屏渲染程序能直接拉出来量。
- 离屏渲染程序改为按外观解析窗口底色，四种图各出浅色与深色两张。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- chart-view：新增配色对比度要求，主色与次级色要能区分。

## Impact

- 新增 `app/Sources/ChartUI/ChartPalette.swift`、`app/Sources/WorkbenchUI/ColumnStatsView.swift`。
- `ChartPanel.swift`、`ContentView.swift`、`ColumnStatsView` 的取色方式。
- `TableWorkbenchUIAudit` 的渲染项与底色。

## 性能与只读

配色只在建色时算一次，20 次二分，不进绘制循环，不影响绘图耗时；release 出图仍是 0.07 秒。只读约束不变，没有新增查询，也没有联网。

## 不做什么

- 不做用户自定义配色（R-VIZ-04 边界已写明）。
- 不为浅色下检查器正文 4.28:1 去改系统语义色，那是系统次要色本身的取值，改它会连带影响全应用所有次要文字。
