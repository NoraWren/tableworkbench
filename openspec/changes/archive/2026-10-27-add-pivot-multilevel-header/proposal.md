# Proposal

## Why

透视结果现在把列维度压成一个扁平列名，写出来是“金额 求和 / 华南 / 直销”。两级列维度要看的是“表头分两层、上面一层合并同类”，现在读起来像一串用斜杠连起来的长标签，多级维度的结构在图上看不出来。R-PVT-04 那条验收因此一直没勾。

## What Changes

- 透视结果携带表头层级：每个结果列带一份从顶层到底层的路径，行维度列各占一层，列维度按“值 × 维度组合”展开成两层。
- 结果网格按层级画多层表头，同层的相同标签横向合并成一个跨列表头。
- 左上角留空，不写“行 / 列”这类占位。
- 冻结首列和表头行：横向滚动时行维度列与左侧行号条保持可见。
- 列名仍保留完整的斜杠串做标识，复制与导出拿到的还是原来那份列名，不受表头显示影响。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- pivot-table：结果呈现部分增加多层表头的契约，对应 R-PVT-04。

## Impact

- DuckDBKit：新增表头层级模型，透视返回结果时一并给出层级；生成 SQL 的列别名不变，仍是一整串扁平名字，保证“在 SQL 抽屉复现”这条不破。
- DataGrid：网格增加可选的表头层级输入，用自绘表头视图替代系统单行表头；冻结首列复用行号条已有的滚动跟随做法。
- WorkbenchUI：透视结果把层级传给网格，SQL 抽屉的结果不传，行为不变。
- 不影响导入、查询、导出、图表的现有路径。

## 不做什么

- 不做斜线表头、合并单元格的样式配置、表头拖拽换位。
- 不做列维度值的小计与总计行。
- 不改基数上限、不改聚合方式、不改 SQL 生成。
- 不给 SQL 抽屉的任意查询结果猜表头层级：只有透视知道自己有几级维度，别的结果按单层显示。

## 为什么现在做

v0.1 其余功能都已验收，这是唯一一处写在需求里、确实还没实现的可见行为。它影响的正是透视最常用的场景（两个维度交叉），补上之后透视才算完整。
